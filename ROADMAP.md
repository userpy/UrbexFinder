# План развития бота для заброшенных мест

Цель первого этапа — проверить, помогает ли бот выбирать места для поездок и возвращаются ли пользователи за новой информацией. Поиск, геолокация, оценки, отзывы, фотографии и отметки об исчезновении уже реализованы; ниже — задачи по развитию и проверке продукта.

## 1. Подготовить регион для пробного запуска

- [ ] Выбрать один город или область и основную аудиторию первого запуска.
- [ ] Отобрать 50–100 мест и проверить координаты, описания, дубликаты и соответствие фотографий.
- [ ] Для каждой карточки указать источник сведений и дату их проверки; неизвестные сведения явно обозначить.
- [ ] Проверить условия использования исходной базы и фотографий, сохранить необходимые указания авторства.
- [ ] Отдельно обозначить состояние объекта и известные условия разрешённого посещения: наличие координат не означает разрешение на вход.
- [ ] Пройти основной сценарий на телефоне: запуск → поиск или геолокация → карточка → открытие карты → возврат к результатам.
- [ ] Проверить резервное копирование production-базы и восстановление из копии до привлечения пользователей.

Готово, когда пользователь может выбрать место в выбранном регионе, увидеть происхождение и свежесть сведений и открыть его на карте.

## 2. Сделать актуальность сведений видимой

- [ ] Добавить состояние объекта: неизвестно, существует, частично разрушен, снесён. Условия доступа хранить отдельно от состояния.
- [ ] Добавить дату последнего подтверждения состояния; не подменять её датой редактирования карточки или загрузки фотографии.
- [ ] Добавить действие «Сообщить об изменении» с выбором причины, комментарием и необязательной фотографией.
- [ ] Показывать непроверенный сигнал об исчезновении уже после первого сообщения, с пометкой о необходимости проверки.
- [ ] Пересмотреть требование предварительно оценить другие места для подачи сообщения: пользователь должен иметь возможность сообщить о проблеме сразу.
- [ ] Пересмотреть автоматическое скрытие после десяти отметок: определить правила проверки, скрытия и восстановления карточки.
- [ ] Сделать очередь сообщений для администратора с действиями «подтвердить», «отклонить», «нужны сведения» и историей решений.
- [ ] Предусмотреть защиту от повторного спама и возможность пожаловаться на отзыв или фотографию.
- [ ] Проверить тестами изменение статусов, права модератора и согласованность видимости в поиске и каталоге.

Готово, когда пользователь видит свежесть сведений, а сообщение об ошибке доходит до решения администратора.

## 3. Измерять полезность

- [ ] Определить события: начало работы, поиск, пустая выдача, открытие карточки, запрос открытия карты, повторное использование, добавление отзыва или фото.
- [ ] Выбрать способ измерения перехода к карте: обычная URL-кнопка сама по себе не сообщает боту о нажатии. Отдельно учитывать запрос ссылки и подтверждённый переход, если последний технически измеряется.
- [ ] Различать дату публикации отзыва и указанную пользователем дату посещения. Переход к карте не считать посещением объекта.
- [ ] Добавить метки источников привлечения через параметры запуска бота.
- [ ] Подготовить простой еженедельный отчёт: активные пользователи, повторные обращения за 7 и 30 дней, пустые поиски, открытия карточек, пользовательские обновления.
- [ ] Определить срок хранения аналитики; не сохранять точную геолокацию в аналитических событиях без необходимости. Проверить существующее логирование координат.

Готово, когда можно проследить путь от привлечения пользователя до выбора места и повторного обращения.

## 4. Провести пробный запуск

- [ ] Подготовить короткое описание бота и примеры карточек для выбранного региона.
- [ ] Договориться о размещении в подходящих местных сообществах и привлечь 30–50 целевых пользователей.
- [ ] Добавить понятную кнопку обратной связи.
- [ ] Провести 5–10 разговоров с пользователями: удалось ли выбрать место, были ли сведения полезны, что помешало, воспользуются ли ботом снова.
- [ ] Наблюдать за использованием в течение четырёх недель; отдельно учитывать пользователей, для которых срок измерения возврата ещё не прошёл.
- [ ] Еженедельно исправлять проблемы, мешающие найти место или получить достоверные сведения.
- [ ] По итогам решить: продолжать в регионе, изменить сценарий или приостановить расширение. Основания — возвраты, реальные истории использования и затраты на актуализацию.

Числа выше — ориентиры для небольшого эксперимента, а не доказанные показатели спроса. Календарный месяц не гарантирует достаточного количества повторных поездок.

## 5. Улучшать выбор по результатам запуска

- [ ] Добавить избранное, если пользователи хотят сохранять места для будущей поездки.
- [ ] Добавить нужные аудитории фильтры: расстояние, тип объекта, свежесть подтверждения, условия посещения.
- [ ] Проверить удобство карты на небольшом прототипе; принимать решение о Mini App после обратной связи.
- [ ] Проверить интерес к уведомлениям об изменениях сохранённых мест; отправлять их только по подписке пользователя.
- [ ] Добавить предложение нового места пользователем с проверкой перед публикацией, если появилась готовность пополнять базу.

## 6. Проверить монетизацию и расширение

- [ ] Узнать у возвращающихся пользователей, за какие дополнительные возможности они готовы платить.
- [ ] Выбрать одну гипотезу: тематические подборки, дополнительные возможности или партнёрства с организаторами разрешённых экскурсий.
- [ ] Проверить спрос конкретным предложением с ценой до разработки полноценной платёжной системы.
- [ ] Посчитать расходы на инфраструктуру, привлечение, проверку объектов и модерацию, включая время владельца.
- [ ] Решить, оправдано ли подключение оплаты, по результатам проверки спроса и расходов.
- [ ] Расширять географию после появления воспроизводимого способа наполнения и обновления базы.

## Что отложить до результатов пробного запуска

- Массовый импорт новых регионов без проверки качества.
- Полноценный Mini App без проверки сценария карты.
- Сложную геймификацию и рекомендательную систему.
- Усложнение инфраструктуры без измеренной необходимости.
- Разработку подписки до проверки готовности платить.

Ближайший порядок работы: регион и данные → актуальность и модерация → аналитика → пробный запуск → улучшения по обратной связи.
