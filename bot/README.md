# Bot

Telegram bot service package.

### Удаление фото из S3 через воркер

Очередь `bot.commands` принимает событие с routing key `places.photo.s3.delete`:

```json
{"object_key": "photos/abc123.jpg"}
```

Хендлер удаляет объект из bucket, заданного `URBEX_S3_BUCKET`. Подключение
настраивается через `URBEX_S3_ENDPOINT`, `URBEX_S3_ACCESS_KEY` и
`URBEX_S3_SECRET_KEY`. Для mini-стека укажите endpoint доступного S3:
собственного сервиса MinIO в этом стеке нет.
Ошибки удаления обрабатываются существующим механизмом retry/DLQ.
При удалении S3-фото через API событие сохраняется в `photo_event_outbox`
в той же транзакции, что и изменение записи фото. Оно содержит `message_id`,
`photo_id`, `place_id`, `object_key` и `deleted_by`. Воркер проверяет таблицу
каждые 5 секунд и публикует события с подтверждением RabbitMQ. При сбое событие
остаётся для повторной отправки. Telegram-фото с `file_id` не создают S3-события.
Перед запуском обновлённого API и воркера примените миграцию `web_009`.
События создаются для новых удалений; ранее удалённые фото не обрабатываются задним числом.
После обновления повторно запустите `rabbitmq-topology`, чтобы добавить binding,
и пересоберите/перезапустите `places-worker` с новой зависимостью boto3.

### Общая галерея фотографий

Кнопка «Фото» в карточке Telegram показывает опубликованные фотографии из
`place_photos` и `web_photos` в общей ленте. Для фотографий сайта бот читает
файл из приватного S3 и передаёт его в Telegram при открытии галереи.
Боту нужны те же переменные `URBEX_S3_*`, что и воркеру.
Новые фото публикуются сразу, без предварительного одобрения (миграция `web_010`).
Она также публикует ранее ожидавшие одобрения фото. Отклонённые и удалённые фото
остаются скрытыми. Уже отправленные сообщения
в чатах остаются; автоматической рассылки новых фотографий пользователям нет.
